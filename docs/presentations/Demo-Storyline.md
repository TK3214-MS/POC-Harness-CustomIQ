# Demo Storyline（30分デモの発表台本）

> [docs/self-guided-demo/30-Minute-Demo-Guide.md](../self-guided-demo/30-Minute-Demo-Guide.md) の各ステップを、聴衆の前でライブ実演する際のナラティブ（語り口）台本です。コマンドそのものの詳細は元のガイドを参照し、本ファイルは「何を、どういう順番で、どう説明しながら見せるか」に特化しています。
>
> 想定シチュエーション: 経営層・技術担当者が混在する聴衆に対して、実機でライブデモを行う場面。発表者は事前に [Speaker-Notes.md](Speaker-Notes.md) の想定質問にも目を通しておいてください。

---

## デモ開始前の一言（重要）

デモを始める前に、必ず次の3点を口頭で明示してください。

1. 「これから見せるのは Local Preview Mode です。実際の Microsoft 製品やお客様の実データには一切接続していません」
2. 「すべてのデータは完全な合成データです」
3. 「この後の画面には、模擬・合成データである旨と、責任あるAIに関する通知が必ず表示されます。これは省略できない設計になっています」

この前置きをしてから実演に入ることで、後続のどの質問にも一貫した姿勢で答えられます。

---

## ステップ1: `health`（0〜3分）

**画面に映すコマンド**: `./scripts/demo/run-demo-cli.sh health`

**語り口**:
- 「まず、このアクセラレータが今どのモードで動いているかを確認します」
- 出力が表示されたら、実行モードが Local Preview であること、Industry Pack が Ready 状態であることを指差しながら説明
- Live Adapter のセクションが表示されたら: 「ここに Work IQ・Foundry IQ・Fabric IQ・Copilot Studio の接続状況が出ますが、いずれも `unavailable` または `verification_required` と表示されているはずです。これは意図した状態であり、エラーではありません」

**指摘するポイント**: 実顧客データが含まれていないことの確認項目が表示されている点

---

## ステップ2: `validate`（3〜7分・前半）

**画面に映すコマンド**: `./scripts/demo/run-demo-cli.sh validate`

**語り口**:
- 「次に、5つすべての Industry Pack が正しく構成されているかを検証します」
- 「これは製造・金融サービス・小売・医療・行政の5業界すべてに対して行われます。業界ごとに個別の検証コードを書いているわけではなく、共通の検証ロジックがすべての業界に対して同じように動作します」

---

## ステップ3: `select-industry`（3〜7分・後半）

**画面に映すコマンド**: `./scripts/demo/run-demo-cli.sh select-industry manufacturing`

**語り口**:
- 「ここで業界を選択します。今回はまず製造業から始めます」
- 「後ほど、この選択を別の業界に切り替えて、プラットフォームのコードが一切変わらないことを実際にお見せします」

---

## ステップ4: アーキテクチャの説明（7〜12分）

このステップはコマンド実行ではなく、口頭説明の時間です。[Architecture-Diagrams.md](Architecture-Diagrams.md) の図（画像化したもの）を画面共有しながら説明してください。

**語り口の骨子**:
- 「共通の基盤の上に、業界固有の Industry Pack が乗っている構成です」
- 「業務コンテキスト・ナレッジ・組織内の関係性という3つの統合レイヤーがありますが、いずれも現在は模擬データで動作しています」
- 聴衆が技術者中心の場合は、ここで [Technical-Presentation.md](Technical-Presentation.md) のスライドに切り替えてもよい

---

## ステップ5: `load-data` → `run-demo`（12〜22分）

**画面に映すコマンド**:
```bash
./scripts/demo/run-demo-cli.sh load-data --industry manufacturing --scale demo
./scripts/demo/run-demo-cli.sh run-demo --industry manufacturing
```

**語り口（`load-data` 実行時）**:
- 「合成データを生成します。実在する企業・部品・サプライヤーの情報は一切含まれません」

**語り口（`run-demo` 実行時、出力が表示されたら順番に指差しながら説明）**:
1. **模擬・合成データに関する開示文**: 「ここに必ず、模擬・合成データである旨が明記されています。これは省略できません」
2. **責任あるAI通知**: 「ここに、このシナリオで人による確認が必要な事項が明記されています」
3. **エグゼクティブサマリー**: 「AI が生成した要約です。この時点ではまだ『提案』の段階です」
4. **推奨される次のアクション**: 「あくまで推奨であり、実行はされていません」
5. **人による承認が必要な事項**: 「ここに列挙された事項は、AI が自動では判断しない設計になっています」
6. **実行モードとトレース/相関ID**: 「実行モードが `local_preview` になっていることを確認してください。監査のためのIDも必ず付与されます」

**さらに深掘りしたい場合**: `scripts/demo/output/last_run.json` をエディタで開き、回答全体の構造（14項目のスキーマ）をそのまま見せると、契約ベースの設計思想が伝わりやすくなります。

---

## ステップ6: Industry Pack の切り替え（22〜26分）— 最重要の見せ場

**画面に映すコマンド**:
```bash
./scripts/demo/run-demo-cli.sh select-industry retail
./scripts/demo/run-demo-cli.sh run-demo --industry retail
```

**語り口（切り替え前に予告する）**:
- 「ここからが今日一番お見せしたい部分です。業界を小売に切り替えます。この切り替えの際、基盤側のコードは一切変更しません。設定とデータを差し替えるだけです」

**語り口（切り替え後の出力を見ながら）**:
- 「エンティティの種類が変わりました（品質問題 → 需要シグナルなど）」
- 「業務ツールやナレッジ文書の内容が、小売業界向けのものに変わりました」
- 「一方で、回答全体の構造（14項目のスキーマ）や、模擬データ開示・責任あるAI通知の有無は、製造業のときと全く同じです」

**任意の追加演出**: 時間に余裕があれば、もう1業界（金融サービス・医療・行政のいずれか）でも同じ手順を繰り返し、「同じコードで何度でも業界を切り替えられる」ことを強調してください。

---

## ステップ7: コストとアーキテクチャの補足（26〜29分）

このステップも口頭説明中心です。

**語り口**:
- 「このアクセラレータ自体はローカル実行のため、今この場でのデモに実コストは発生していません」
- 「実際に Azure 環境へデプロイした場合のコストについては、現時点で確定した数値をお出しできません。実環境での検証がまだのためです。価格は必ず Microsoft の最新の公式情報でご確認いただく前提でお話ししています」

---

## ステップ8: `evaluate` → `generate-summary`（29〜30分）

**画面に映すコマンド**:
```bash
./scripts/demo/run-demo-cli.sh evaluate --industry manufacturing
./scripts/demo/run-demo-cli.sh generate-summary
```

**語り口**:
- 「最後に、今の実行結果を評価基準に照らして自動チェックします。この評価は、開示文の有無や引用の有無など、機械的にチェックできる範囲に限定されています」
- 「完了サマリーには、『検証済みの機能』と『未検証の機能』が両方明記されます。これをそのままお客様に共有する前提の資料として設計しています」
- サマリー内の「Features Not Verified」セクションを指差しながら: 「ここに、Live Adapter が実際の Microsoft 製品に接続していないこと、実 Azure 環境へのデプロイが未実施であることが、包み隠さず記載されています」
